## 1. 產品目標

這個工具讓「借錢投資 ETF」的人在動手前，看清楚自己撐不撐得住每月還款。
這一版要解決的是「看得懂、用得順、知道界線在哪」：

| 編號 | 使用者故事 | 為什麼重要 |
|---|---|---|
| 27 | 身為想借錢投資的人，我想知道「以我的條件，最多能借多少才夠安全」，以及貸款金額和每月能自掏的錢怎麼影響風險 | 目前只能自己一直改數字試，找不到安全邊界 |
| 38 | 身為一般使用者，我想看到白話的標題和名稱 | 「MC 宇宙」「Accounting Trace」「Block Bootstrap」這類詞讓人看不懂 |
| 35 | 身為使用者，我想把設定都調好再一次計算 | 每拖一次拉桿就整頁重算，設定多時會卡，也會看到調到一半的結果 |
| 39 | 身為求職展示的對象（外國面試官），我想用英文操作 | 目前只有中文 |

排序依使用者指定：27 → 38 → 35 → 39。

## 4. 第 27 項：安全邊界（反向求解＋敏感度熱圖）

### 4.1 計算核心 API（衝刺 1，RD 實作、QA 依此寫驗收測試）

在 `engine.py` 新增：

```python
@dataclass(frozen=True)
class SolveResult:
    field: str          # "principal" 或 "salary_cap"
    value: float | None # 找到的值；範圍內沒有任何值達標時為 None
    ruin_rate: float    # value 對應的蒙地卡羅破產率；value 為 None 時是最接近達標那一端的破產率
    target: float       # 目標破產率上限
    status: str         # "ok"、"all_meet"（整個範圍都達標）、"none_meet"（整個範圍都不達標）
    evaluations: int    # 實際跑了幾次模擬


def solve_for(df, params, field, target_ruin, lo, hi, step) -> SolveResult: ...


def sensitivity_grid(df, params, principals, salary_caps, mc_paths=1000) -> pd.DataFrame: ...
```

`solve_for` 規則：

- `field="principal"`：在 `[lo, hi]` 之間、以 `step` 為單位，找**最大的**貸款本金，使蒙地卡羅破產率 ≤ `target_ruin`。
  - `hi` 就達標 → `status="all_meet"`、`value=hi`。
  - `lo` 都不達標 → `status="none_meet"`、`value=None`。
- `field="salary_cap"`：找**最小的**每月自掏上限，使破產率 ≤ `target_ruin`。
  - `lo` 就達標 → `status="all_meet"`、`value=lo`。
  - `hi` 都不達標 → `status="none_meet"`、`value=None`。
- 回傳的 `value` 一定是 `lo + k*step`（不超過 `hi`）；`hi` 本身不在格點上時也要檢查 `hi`。
- 其他設定一律沿用 `params`。不可修改傳入的 `params`（用 `dataclasses.replace`）。
- 亂數：`params.seed` 是 None 時固定用 42，讓每次評估用同一組抽樣（共同隨機數），破產率才會隨本金單調變化。
- 用二分搜尋；`evaluations` 不可超過 `ceil(log2((hi - lo) / step)) + 3`。
- 下列情況丟 `ValueError`（中文訊息）：
  - `field` 不是上述兩者；
  - `target_ruin` 不在 (0, 1)；
  - `lo > hi`、`step <= 0`；
  - `lo < 0`、`principal` 搜尋的 `lo` 為 0；
  - 資料不足以跑蒙地卡羅（`n < 2`）。

`sensitivity_grid` 規則：

- 回傳 DataFrame：`index` = `principals`（依傳入順序），`columns` = `salary_caps`（依傳入順序），值是蒙地卡羅破產率（0～1）。
- 每一格只改本金與自掏上限，其他設定沿用 `params`；所有格子用同一個種子（`params.seed`，None 時用 42），`mc_paths` 用參數值。
- 一致性：`mc_paths` 等於 `params.mc_paths` 時，(`params.principal`, `params.salary_cap`) 那一格必須等於 `run_summary(df, params_with_seed)` 的蒙地卡羅破產率。
- 單調性（同一組抽樣下）：
  - 同一列中，自掏上限越高，破產率不升。
  - 同一欄中，本金越高，破產率大致不降（補充保費門檻可能造成極小例外，容許 0.01）。
- 效能：6×6 格、1000 條路徑、226 個月資料、84 個月貸款，本機 10 秒內完成。

### 4.2 畫面（衝刺 2，依 UI/UX 設計）

PO 決定的範圍：

- 新增一個「安全邊界」區塊，放在主要結果之後。因為要跑很多次模擬，**按按鈕才計算**，不自動跑。
- 兩個答案：
  - 「以目前其他設定，最多能借多少」：本金搜尋範圍 10 萬～目前本金的 10 倍（上限 1 億），單位 10 萬。
  - 「最少要能每月自掏多少」：0～50 萬，單位 1,000 元。
- 目標破產率可選 1%、5%、10%，預設 5%，網址參數 `tgt`（值為 1、5、10）。
- 熱圖：本金與自掏上限各取目前值的 0.5、0.75、1、1.25、1.5、2 倍（自掏上限為 0 時改用 0、5,000、10,000、20,000、30,000、50,000），標出目前設定的那一格，格內顯示破產率。
- 算過的結果要寫進可下載的報告。
- 白話結論句，例如：「以目前其他設定，要讓破產機率在 5% 以下，最多可以借 820 萬（你目前設定 500 萬）。」
- 第 35 項做好後，這個按鈕的行為要和「開始計算」一致（設定變了就標示過期）。

## 6. 第 35 項：開始計算按鈕

- 第一次打開（包括從分享連結打開）時自動計算一次，讓人直接看到結果。
- 之後只要改了任何會影響計算的設定，**不重新計算**，畫面保留上一次的結果，並在結果最上方清楚標示「設定已變更，結果尚未更新」，旁邊有「開始計算」按鈕；側欄也要有同一顆按鈕。
- 側欄提供「自動重算」開關（預設關閉），打開時恢復現在的行為（每次調整都重算）。網址參數 `auto`。
- 不影響計算的操作立即生效、不需要按鈕：切換逐月追蹤的進場月份、下載、展開說明。
- 輸入錯誤（例如自訂報酬率格式錯誤）立即顯示，不必等按按鈕。
- 網址列一律反映目前的輸入（即使還沒按計算），重新整理後會用目前的輸入自動算一次。
- 安全邊界區塊：設定改變後，已算出的安全邊界也標示為過期。
- 驗收要包含：連續改三個設定只觸發零次計算、按一次按鈕只觸發一次計算（可用 mock 計數 `engine.run_summary`）。

## 7. 第 39 項：英文介面

- 側欄最上方加語言切換（中文／English），網址參數 `lang`（`en` 為英文，預設中文）。切換語言不改變任何設定與結果。
- 英文模式下，以下都必須是英文：主頁、說明頁、可下載的報告、圖表、表格、提示與錯誤訊息（包括 `market_data.py`、`engine.py` 丟出的訊息）。
- 例外：ETF 的中文名稱（來自資料）、使用者自己輸入的文字。
- 金額格式：英文模式用 `NT$`。
- 做法由 RD 決定，建議新增一個文字模組（例如 `i18n.py`），由 UI/UX 提供英文文案。
- 驗收：英文模式下，把畫面上所有文字收集起來，扣掉 ETF 名稱後不可有任何中日韓文字（QA 寫成自動測試）。

## 9. 風險

| 風險 | 處理 |
|---|---|
| 二分搜尋遇到破產率不單調 | 用共同隨機數；QA 用性質測試檢查；結果仍以實際模擬值回報 |
| 安全邊界計算太慢 | 按鈕觸發、路徑數減少、顯示進度 |
| 開始計算按鈕和 Streamlit 的重跑機制衝突 | 用 session_state 保存「最後一次計算的參數與結果」，比對參數判斷是否過期，不用 `st.form`（側欄有依勾選而出現的欄位，放進 form 會出問題） |
| 英文化範圍大、容易漏 | QA 用自動掃描中日韓文字的測試把關 |
| 多人同時改同一個檔案 | 依第 2 節的檔案權責；同一衝刺只有 RD 改程式碼 |
